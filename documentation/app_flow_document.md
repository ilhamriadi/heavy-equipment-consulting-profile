# App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new visitor arrives at the site, they land on the public homepage by entering the domain or clicking a shared link. There is no public account creation because the site is designed as a company profile. For content administrators, a hidden route at `/admin` provides access to the admin sign-in page. Administrators enter their registered email address and password to log in. If the password is forgotten, they can click a “Forgot Password” link, which prompts them to enter their email. An email with a secure reset link is sent, allowing them to choose a new password. After resetting, they return to the login form and can sign in with their updated credentials. Signing out at any time is done by clicking a logout button, which clears the session and returns the user to the public homepage.

## Main Dashboard or Home Page
Upon signing in, administrators arrive at the admin dashboard, which features a left-hand navigation sidebar listing content sections such as About, Services, Gallery, and Contact Form Settings. At the top, a header displays the site title, a theme toggle button to switch between light and dark modes, and a logout control. In the main content area, the default view shows an overview of recent updates and quick links to each section. Public visitors see a one-page scroll layout with a fixed header that contains navigation links to each section, a theme toggle, and a prominent WhatsApp chat button at the bottom corner.

## Detailed Feature Flows and Page Transitions
When an administrator clicks the About link in the sidebar, the main area loads an About editor. They see the current heading, body text, and an image picker. Editing text fields directly updates local state. After making changes, they click Save, which calls the `/api/content/about` endpoint. If successful, a confirmation message appears and the updated content is immediately reflected on the public page after a refresh. In the Services section, admins view a list of service items in card form. They can click an Add Service button to open a modal form where they enter title, description, and upload an image. Submitting the form sends a POST request to `/api/content/services`, and the new service appears in the list. Editing or deleting a service follows a similar pattern via the card’s edit and delete controls, calling PUT or DELETE endpoints. The Gallery section lets admins manage image assets. Clicking Add Image opens a file chooser; after selecting files, an upload progress indicator appears. On completion, images are stored and listed with captions that can be edited inline. The Contact Form Settings page allows administrators to configure the email address that receives submission notifications. For public users, filling out the contact form at the bottom of the page involves entering name, email, and message. Upon hitting Submit, the form calls `/api/contact`. If successful, a thank-you message replaces the form; on error, inline validation messages guide users to correct mistakes. Navigating between admin pages does not require a full page reload thanks to client-side routing, while public users scroll smoothly between anchored sections.

## Settings and Account Management
In the admin sidebar, a Settings link leads to account management controls. Administrators can update their email address and change their password by entering the current password and the new credentials. Submitting these changes calls the `/api/auth/user` endpoint. A success banner confirms updates, and they remain signed in to continue editing content. The theme toggle at the top of both admin and public pages stores the preference in local storage. Administrators return to content editing by clicking the Dashboard or any section link in the sidebar.

## Error States and Alternate Paths
If an administrator enters incorrect credentials, an error banner appears above the login form explaining that the email or password is invalid. During content saving, if the API responds with a validation error or network failure, an inline error message appears next to the relevant field or upload control. Administrators can retry failed actions. Public users who attempt to submit the contact form with missing or invalid input see field-level error messages and remain on the form until corrections are made. If the user’s connection is lost, a banner at the top warns of offline status; actions requiring a network call are disabled until connectivity returns. Any unauthorized access to the `/admin` route redirects back to the sign-in page with a message about needing to log in.

## Conclusion and Overall App Journey
A public visitor experiences a smooth, informative journey by scrolling through the single-page layout, toggling themes, initiating a WhatsApp conversation, or sending a message via the contact form. Meanwhile, an administrator follows a clear process to sign in at `/admin`, navigate the dashboard, and update each content section through intuitive editors and forms. They manage images, services, and contact settings while handling errors gracefully. Throughout, the theme toggle and seamless routing maintain consistency. This flow ensures that public-facing content remains fresh and engaging, and that administrators can efficiently manage the site from sign-in to daily updates.
